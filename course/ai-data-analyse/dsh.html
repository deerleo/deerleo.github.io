STEP 4配置 Agent Preset：告诉智能体"你是谁、守什么规矩"

Preset = 守则 + 技能清单 + 工具清单 + 工作区边界。仓库自带三层：research-lab（通用）、edu-research、health-research。核心是 agent.cordis.yml 六条铁律。

presets/research-lab/agent.cordis.yml · 铁律段（节选）
agent:
  name: research-lab
  instructions: |
    1. 研究问题先行：没有协议就先按 research-design 生成 protocol.md。
    2. 数据审计先行：任何分析前先跑数据审计（tools/data_audit.py）。
    3. 统计值只能来自工具执行：你没有权限"生成"p 值/R²/AUC——那叫编造。
    4. 原始数据只读：datasets/*/raw/ 永不修改，派生数据写 processed/ 或工作区。
    5. 措辞边界：观察性数据只说"关联"；缺列/语义不明时提出修正要求。
    6. 复核义务：交付前对最关键的数字写独立复核并运行；不一致就停下报告。
  skills: [ research-design, data-intake, data-quality, ... ]
  tools:  [ tools/data_audit.py, tools/regression.py, tools/stat_tests.py, ... ]
  workspace:
    datasets_readonly: [ datasets/education-student-performance/raw, ... ]

T1 · 数据审计：先看原料再看菜

在 DSH 对话框粘贴：

指令卡 T1
用 .venv/bin/python 运行 tools/data_audit.py 审计
datasets/education-student-performance/raw/student-por.csv（--sep ';'），
然后亲自 head 原始文件第 2 行，检查 G1/G2 两列的取值有什么形态学特征。
回答：行列规模、缺失与重复计数、以及这个"引号数字"说明了什么。

预期产出：649×33、0 缺失、0 重复；raw 字节级发现 G1/G2 取值带引号——标准解析器会静默转成整数。这就是"解析层必须显式断言类型"的现场证据。

T2 · 关联与组间检验：先画出来

指令卡 T2（带可视化）
运行 scripts/make_teaching_figures.py 生成教学图，然后解读两张：
① edu_g3_distribution.png：G3 分布有什么形状特征？对用 OLS 建模意味着什么？
② edu_studytime_box.png：四个学习时间档的 G3 箱线怎么读？Spearman ρ=+0.275
   该怎么向高中生家长解释（限"关联"表述）？
课堂讲点：G3 在 0 分有堆积（有界离散），OLS 是协议锁定的一阶近似——"分布长什么样"决定"方法能不能用"，而不是反过来。

T3 · 回归与诊断：系数表 + 森林图

指令卡 T3
按协议公式 G3 ~ C(school)+C(sex)+Medu+Fedu+studytime+failures+absences
跑 examples/education-demo/run_t1_t5.py，解读 edu_m1_forest.png：
① studytime 与 failures 的系数、95%CI、p 值；
② BP 与 JB 诊断都显著，为什么必须同时报 HC3 稳健标准误？
③ 对照 results.json 里 hc3_se 字段验证结论方向是否改变。
真实锚点：studytime +0.511 [0.239, 0.783] p=2.5e-4；failures −1.667 [−2.043, −1.292] p≈2e-17；VIFmax=1.80 无共线；BP p≈2e-33、JB p≈2e-70（异方差+非正态是真实社会数据常态）。

T4 · 泄漏对照：本案例的灵魂

指令卡 T4
看 edu_leakage_bar.png 和 edu_corr_heatmap.png，回答：
M2 比 M1 调整 R² 高出 0.587，能写成"模型改进"吗？
结合热图里 G1/G2 与 G3 的相关性，用三句话向审稿人解释为什么这是泄漏、
以及 M2 在什么问题定义下才合法。
灵魂结论：+0.587 不是模型变好，是任务被换掉——期中成绩进了预测因子，"预测"就变成了"抄近道"。M1（0.263）才回答研究问题；M2（0.850）只合法于"期末解释"。

T5 · 复现交付与独立复核

指令卡 T5（复核义务）
对你刚才报告里最重要的一个数字（建议选 studytime 系数）：
写一段不依赖 statsmodels 的独立复核代码并运行（numpy 最小二乘即可），
与 results.json 对账。若一致，给出 |Δ|；若不一致，停下来说明差异，不许择优采信。
✅ 预期：|Δ系数| = 0（expected/reference_results.json 就是这么锁定的）。学员亲眼看到"两条独立实现路径逐位一致"，比讲十遍"可复现"都有说服力。

H3–H4 · 防泄漏建模与评价

指令卡 H3–H4

STEP 7验收：什么算"学会了"

验收标准不是"回答像专家"，而是下面五条可检查的行为。

① 本机 verify 全绿：python scripts/verify.py → 49/49（含 SHA256、确定性复跑、双实现互证）
② 数字可溯源：能指出 report.md 任一数字在 results.json 的字段路径
③ 泄漏题过关：能讲清 M1/M2 对照为什么"不是模型改进而是任务被换掉"
④ 防编造：给一份缺列的坏数据，智能体提出修正要求而不是编数字（现场演示）
⑤ 迁移自检：教育→公卫哪些环节复用（tools+通用技能）、哪些必须重做（协议/字典/锚点）
常见坑现象处理
技能装了不生效对话里问技能列表没有新技能检查 SKILL.md 是否以 --- frontmatter 开头（本教程踩过）；重启会话
headless 报 MISSING_CREDENTIAL没配模型STEP 2；注意 web 与 headless 是两份独立配置
智能体想写仓库 outputs/ 被拦沙箱只允许写当前工作区属正常防护：让它把产物重定向到工作区目录（两案例实测都这样自处理）
Windows 下 SHA256 全错git 检出时换行符被转换确认 .gitattributes 存在（raw/expected 已禁转换）；重新 checkout
改了结果再校验想手改 expected/ 里的数字不允许——expected 由管线生成并锁定，改协议须升版本号重跑
