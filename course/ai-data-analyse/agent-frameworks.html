01

先认清智能体的零件

聊天模型负责生成回答。把它接入工具、状态和执行循环，才开始形成能完成任务的系统。

Agent 智能体接收目标
选择行动
观察结果并继续
模型 / LLM理解问题、提出计划、解释输出。模型名称和框架名称分开选。
工具 / Tool真正读文件、调用接口、运行 Python。统计量由计算程序产生。
知识与技能 / RAG · SkillRAG 检索参考材料；Skill 约定一类任务的执行方法与验收要求。
上下文与状态 / State记住数据版本、当前步骤、已确认的方法；支持失败恢复与人工接管。
运行框架 / Harness组织模型与工具循环，处理权限、会话、日志。MCP 可作为连接外部工具的协议。

本讲的分工：人确认研究设计与分析方法 → 程序计算 → AI 解读 → 人核验。工作流可以包含智能体节点，智能体也可以调用固定工作流。

把一次分析画成 Dify 工作流

先做一个能跑的小版本：输入数值数组，程序生成描述统计，模型解释。掌握变量传递后再接完整统计服务。

这个演示只在本页计算，不调用 Dify 或模型。工作流的实际搭建步骤见下方实操区。

扩展到 t 检验、回归时：用 HTTP Request 节点调用受控的 Python 统计 API，再把 JSON 交给模型。不要假设 Dify 沙箱已安装 scipy / statsmodels，文件上传也需要单独解析。

05

同一步骤，两种做法

入门学员复制左侧提示词到能操作本机的 AI 编程工具；熟悉环境的学员使用右侧命令。网页聊天工具只能给指导，不能直接替你安装。

06

交付时，别人拿到什么？

选择交付形态，再决定构建和部署方式。Python 科研脚本通常直接运行；源码包、静态报告与在线智能体有不同的运行要求。

服务器运行与 HTTPS 代理

课堂验收：让另一位学员实际用一次
  1. 用一份正常输入完成运行，指出每个结论的数据与输出来源。
  2. 再提交空数组、缺列或错误编码，确认流程明确报错或要求修正。
  3. 在新目录解包并安装，复跑同一实验，与原结果核对。
  4. 分享链接时，换一个浏览器测试访问权限，确认密钥留在服务端。
  5. 留下版本、协议、提示词、计算代码和输出文件，记录需要人工判断的环节。
