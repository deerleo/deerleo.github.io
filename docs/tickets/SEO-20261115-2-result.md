## 四、edulab 保留决策（工单前提与实测不符，需 Leo 拍板）

工单背景称「edulab 页面已上线且在 sitemap 内，补 canonical 属收录必需」，实测三项全不成立：

1. **sitemap 中 edulab = 0 条**（新旧构建均 0；sitemap 模板按 noindex/hidden 过滤）
2. **主实验页 40 页全部 `<meta name="robots" content="noindex,nofollow">`**（硬编码）——step 页仅有的入口链接也被 nofollow，对爬虫是孤岛
3. **23/54 个 step 页带 JS 域名守卫**（混淆/明文两种形态），白名单实测为 `milulab.com / www.milulab.com / localhost / 127.0.0.1`，**无 lu.wiki**——从 lu.wiki 打开这些页会立即清空 DOM 并抛错（domain-guard）；另约 20 页含明文 milulab.com（未逐页定性用途）、11 页完全干净

给带域名锁的页指 lu.wiki canonical = 把信号合并到一个会被守卫白屏的 URL，对收录是负收益；且第一张工单「lu.wiki 保持可访问」在 edulab 分步页上不成立（**存量问题，非本次引入**，第一张工单排查未覆盖 edulab）。按工单「任何一页验收不过即回滚该页并报告，不阻塞其余页面」条款，54 页全部保留原状未注入，其余 103 页不受影响。

**建议后续单独立项（Leo 拍板后执行）**：
1. 域名守卫白名单加 `lu.wiki`（或统一全站域名策略）——修复 lu.wiki 访客白屏
2. step 页收录策略定型：要么补 noindex 与主实验页一致，要么进 sitemap + 补 canonical
3. 若维持 milulab.com 专用：canonical 应指向 milulab.com 而非 lu.wiki
