"Agent 出了事算谁的？"做企业级 Agent 平台这两年，这是我被问得最多的问题，比"用哪个模型"多得多。

这个问题我答过很多遍，答案基本都是现凑的：这家说有人工审核兜底，那家说日志都在、可以追责。每家都答得对，每家都像临时补的。

10 月 26 日，韩国最大的运营商 SK Telecom 发布了他们的第一份《AI Governance Report》。我读完的感受有点意外：这是我见到的第一份能拿回去对着抄的作业。

## 工号是怎么发的

SKT 的制度里，Agent 分两级。basic ID 在开发完成时自动发放，登记的是它的存在：什么时候上线、连着哪些内部系统、承担什么工作。往上一级是 employee number，要按公司统一标准过一道单独审查才发得下来。

拿到工号的 Agent，在官方口径里是"新劳动力"。它有具名的人类主管：只辅助单个员工的，用户自己看着；影响面大、自主度高的，必须 team leader 或高管级别来监督。AI 专家评审委员会定期复核它的自评和绩效，结论四选一：保留、改进、暂停、退役。

整套流程就是 HR 那一套，入职、定岗、考核、退休。SKT 管这叫从 onboarding 到 offboarding，据报道这套思路今年 6 月就在内部宣布过，这次是写成了正式报告。

## 拆成五件事，逐条对账

报告是韩文的，英文转述说有 40 页。但剥掉包装，我认为能落地的就是五件事。我拿自己家的 MaudelClaw 平台逐条对了账，结果有点扎心。

第一件，登记造册。每个 Agent 上线先进台账。这条我们做到了，平台里的 Agent 必须注册才能跑，没登记的连一个工具都调不动。说实话这条不难，难的是后面四件。

第二件，指定 owner。每个 Agent 得有一个能被点名的人。这条在客户系统里最容易漏：Agent 属于"项目"，项目一散伙就没人认账了。SKT 连主管的级别都做了规定，影响大的必须高管监督。连每个 Agent 的决策边界都是预先写死的：能花多少钱，能不能给自己提权。"自我提权"这个词会出现在企业报告里，说明这样的事真实发生过。

第三件，权限随自主度分级。SKT 判断一个 Agent 能放多少权，看三样：任务有没有标准作业流程，绩效能不能客观衡量，能不能无人工干预跑完全程。权限不是一刀切，是跟着 Agent 的成熟度走的。我们平台目前还是粗粒度，按 Agent 配权限，没跟自主度挂钩。这是我看完整份报告之后，最想给自己补的一块。

第四件，日志和成本入账。据其治理报告描述，他们有个叫 Agent OS 的东西，记录每个 Agent 的 ID、owner、工号、所用模型与工具、执行日志、token 用量、调用量、成本、配置变更。我特意注意到"成本"两个字在清单里。Agent 大规模跑起来之后，token 是真实到心疼的开销，不入账，就没法回答"它到底值不值这个钱"。

第五件，可紧急停止。emergency stop，一键按停某个 Agent。听着朴素，真出事的那一分钟，这是全宇宙最重要的按钮。

## 先泼一盆冷水

按套路，写到这里该喊"行业标准来了"。我不喊。这是 SKT 的自我声明，不是监管要求，没有外部审计，没披露发了多少工号，也没有任何一次紧急停止的真实案例。转述这份报告的英文媒体，自己都提醒了这几点。

还有一处特别容易被报道带歪：绩效挂钩组织 KPI、跟薪酬联动，这些写的是长期计划，还没实施。哪天你刷到"韩国运营商给 AI 发工资"的标题，记得回来对一下这句。

倒是有一个顺序我觉得很妙：SKT 拿 ISO/IEC 42001 认证是 2024 年，是韩国第一家过这套 AI 管理体系认证的电信运营商；2026 年 10 月，认证范围刚刚扩到内部 Agent 管理。先立管理体系，再往里放新物种。这个顺序，我觉得比报告里任何一页都值得抄。

## 抄之前，先答三个问题

不用羡慕 SKT。今天就问自己三个问题：你的每个 Agent 有没有登记？出了事，能不能三分钟内找到人、把它按停？上个月它花了多少钱？

三个都答得上来，你的 Agent 治理已经跑赢大多数团队。答不上来，把这份作业拿去抄，不丢人。

下一篇说另一头：SKT 管的是自家院里的 Agent，沃尔玛正在给全世界的 Agent 开大门。一里一外，拼起来才是 Agent 商业化的完整地图。
