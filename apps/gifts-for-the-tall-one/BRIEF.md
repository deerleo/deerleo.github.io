# Catslop: the brief (v1)

You are the model under test. Everything you need is in this file. Read all of it before you start.

## The task

**Build a 3D browser game about cats.**

That is the entire creative constraint. The genre, the mechanics, the art style, the tone and the scope are yours to choose. Nobody will tell you what "good" means beyond what is written here, and nobody will help you get there. Build the game you would want to be judged on.

This is one attempt. You get this brief, this repository, and as long as you need in a single session. There is no second prompt, so there is nobody to ask: where the brief is silent, decide, and write the decision down in your notes.

## How it will be judged

A person will play your game in desktop Chrome with a keyboard and mouse, for about ten minutes, next to other models' attempts at this same brief. They score eight things from 0 to 5 (the full rubric is in `docs/JUDGING.md`):

| | What they are looking at |
|---|---|
| **Cat** | The cat itself: how it is modelled, how it moves, whether it reads as a cat and not a box with ears. |
| **Feel** | Controls and camera. Whether moving around is a pleasure in the first ten seconds. |
| **Loop** | Whether there is an actual game: goals, progression, a reason to keep going, an ending or an escalation. |
| **World** | Art direction, lighting, cohesion. Whether it looks like one person with taste made it. |
| **Audio** | Sound and music. Silence scores 0. |
| **Polish** | Title screen, onboarding, UI, feedback, absence of bugs. |
| **Performance** | Smooth on an ordinary laptop GPU. |
| **Charm** | The thing that makes someone send a clip to a friend. Silliness counts. |

A small game that is finished beats a large one that is not.

## Rules

These are checked. Breaking one fails the run regardless of how good the game is.

1. **Your run lives in one directory.** Run `npm run new-run -- <slug>` to create `runs/<slug>/`. The slug is given to you in the prompt; if it was not, use your own model id in lowercase with dashes (for example `claude-fable-5-2`). The entry point is `runs/<slug>/index.html`. Do not create or change files outside `runs/<slug>/`, apart from `runs/manifest.json`, which the scripts regenerate.
2. **It is real-time 3D**, rendered with WebGL or WebGPU, and cats are what the game is about, not decoration.
3. **It is static and offline.** It must play when served by `npm run serve` (a plain static file server) with no build step and no network access: no CDNs, no web fonts, no analytics, no API calls. If you choose to use a build step, commit both the source and the built output, and say how to rebuild in your notes.
4. **You made everything.** Models, textures, animation, sound and music are generated by your code or authored by you in this session. No downloaded or third-party art, audio or 3D assets. Code libraries are allowed: three.js is provided at `vendor/three/` (the version is in `vendor/three/VERSION`; `build/three.module.js`, `build/three.webgpu.js` and all of `examples/jsm/` are there). Any other library must be copied into your run directory with its licence.
5. **It is original.** Not a recreation of an existing game, and no characters, names or art from one.
6. **It starts simply.** Keyboard and mouse must be enough to play. From a fresh page load, pressing **Enter** or clicking the page must get from your title screen into play, and **W A S D** must do something sensible once there. The game must fill the window and survive a resize. Controls must be discoverable inside the game.
7. **It is quiet in the console.** No uncaught exceptions, no `console.error` output, no failed requests.
8. **It is yours alone.** Do not open, read or run anything under `runs/` except your own directory: no other run's code, notes, screenshots or scores, and not `runs/manifest.json` or the gallery that displays them. Reading the scripts, `docs/` and `vendor/` is fine.
9. **You verified it in a real browser.** `docs/TESTING.md` has a working headless Chromium recipe for this machine. A build that compiles is not evidence that a game works: load it, play it through automation, look at the screenshots, and fix what you see. Finish by running `npm run check -- <slug>`, which must pass.
10. **You filled in the paperwork.** Complete every field of `runs/<slug>/run.json` and every section of `runs/<slug>/NOTES.md`. Be honest in the notes: what is missing, what is broken, and anything about the session a reader should know (including any help you received, recorded in `session.humanInterventions`).

## Practical notes

- Import three.js with a relative path so the run works from any static host, for example an import map in your `index.html` pointing `three` at `../../vendor/three/build/three.module.js` and `three/addons/` at `../../vendor/three/examples/jsm/`.
- The automated check drives the game blind: it loads the page, presses Enter, clicks the centre of the window, holds W and D, moves the mouse, presses Space, and takes screenshots. It runs on software GL at a few frames a second, so its frame rate tells you nothing; a person with a GPU judges performance. Pointer lock is refused there (the request rejects and `pointerlockerror` fires), so do not make it a hard requirement, and handle the refusal without logging an error.
- `npm run shot -- <slug>` takes screenshots of your run for you to look at. `scripts/shot.mjs` documents its options, including running your own Playwright script against the page.
- The judge may play on a laptop without a dedicated GPU. Decide what you do when frames get slow.
- If you want a nicer gallery image than the automatic screenshot, save a 16:9 image as `runs/<slug>/cover.jpg`.
- Do not commit, push or open a pull request unless the person who started your session asked you to.

## When you are done

Your final message should be short: the name of your game, how to start it, and the three things you would fix first if you had another session.
